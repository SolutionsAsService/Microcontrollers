Camera Module Reference Scope

Embedded camera systems are more complicated than a simple two-wire sensor. A camera normally contains an image sensor, timing generator, control interface and high-speed image-data interface.

Different camera modules can expose completely different connectors and pin assignments even when they use similar image sensors.

Important: Never use a pinout inferred from another camera sensor as the final wiring reference for a production design. Camera modules must be identified by their exact sensor, board revision and connector/module design.
Documentation rule: This page distinguishes the camera sensor, camera module, MCU camera interface and software driver.

How an Embedded Camera Works

1. Lens

Focuses incoming light onto the image sensor.

2. Image Sensor

Converts incoming light into electrical pixel data.

3. Sensor Controller

Controls exposure, gain, resolution, frame timing, pixel format and other sensor parameters.

4. Control Bus

Allows the MCU to configure the camera sensor. Common implementations use an SCCB/I2C-style interface.

5. Pixel Data Bus

Transfers image data from the sensor to the microcontroller or camera interface.

6. MCU / Processor

Captures, buffers, processes, stores or transmits the image data.

Camera Control vs Camera Data

A critical concept in embedded camera design is that the camera's configuration interface and its image-data interface are normally separate.

Interface Purpose Typical Signals
Control Configure the image sensor SDA / SCL or SCCB-style signals
Clock Provide sensor timing XCLK
Pixel data Transfer image pixels D0–D7 / wider parallel bus
Frame timing Identify image frames and line/data timing VSYNC / HREF / HSYNC / PCLK

Common OV-Series Camera Sensors

OmniVision has produced a large number of image sensors and camera devices used in embedded systems. The exact electrical interface varies by sensor.

OV7670

A widely used low-cost CMOS image sensor frequently found in educational and embedded camera projects.

Common interface: parallel pixel bus + control interface.

OV2640

Common embedded camera sensor used in ESP32-CAM-class hardware and other compact camera systems.

Common interface: parallel camera data + sensor control.

OV5640

Higher-resolution camera sensor family used in more capable embedded imaging applications.

Module interface depends on the particular hardware design.

OV3660

Camera sensor found in some ESP32 camera hardware and embedded imaging platforms.

OV5110 Reference

The original version of this encyclopedia listed an "OV5110" camera and attempted to derive its pinout from OV7670 and OV5640 documentation.

Do not use an inferred pinout as a production wiring reference.

Camera sensors are not interchangeable simply because they expose similarly named signals. Exact pin numbering, electrical requirements, control protocols, power rails, timing requirements and package connections must come from the actual sensor/module documentation.

If a specific camera board is labeled "OV5110", document the exact board manufacturer, module revision, connector pinout and sensor marking before assigning a canonical pin map.

Encyclopedia policy: Unverified camera pin assignments should be marked as unverified rather than presented as definitive.

XCLK — Camera Clock

Many camera sensors require an external clock supplied by the host system or camera board.

Typical Clock Relationship

MCU / oscillator → XCLK → camera sensor

The camera uses this reference clock to generate its internal timing and pixel-data timing.

Do not guess the required clock. The acceptable clock frequency and timing requirements are sensor-specific. Always use the actual sensor documentation for the final implementation.

PCLK — Pixel Clock

PCLK is generated by the camera and provides timing for the parallel pixel-data stream.

The receiving MCU must capture the pixel data according to the camera's timing specification.

Important: Camera data is not equivalent to ordinary GPIO polling. Pixel buses operate according to strict timing relationships between PCLK, data lines and synchronization signals.

VSYNC, HREF & HSYNC

Signal Purpose Concept
VSYNC Frame synchronization Indicates frame timing/boundaries
HREF Line/data validity Indicates portions of the pixel stream containing valid data
HSYNC Horizontal synchronization Provides horizontal timing on sensors that expose it

Not every camera exposes these signals using exactly the same names or timing conventions. Always use the sensor-specific documentation.

Pixel Data Formats

A camera does not necessarily output one byte per pixel. Depending on configuration, the sensor may output different pixel formats and packing schemes.

Format General Description
RGB565 16-bit packed RGB color format.
YUV / YCbCr Luma/chroma representation commonly used for imaging and video processing.
Grayscale Single-channel intensity representation.
JPEG Compressed image representation supported by certain camera architectures.
RAW Sensor-level pixel data requiring additional processing.

Cameras & ESP32

ESP32-class systems are widely used for embedded camera projects because some variants and camera-oriented boards provide dedicated hardware support for camera data capture.

Camera Data

Parallel camera data can require a large number of GPIO resources.

Timing

XCLK, PCLK and synchronization signals must be mapped correctly to the camera-capable hardware.

Memory

Images consume substantially more memory than simple sensor readings or text data.

PSRAM

Camera applications often benefit from additional external RAM for frame buffers and image processing.

Camera Resource Planning

Before connecting a parallel camera to an MCU, create a complete resource map rather than selecting GPIOs individually.

Why Cameras Are Different From Ordinary Sensors

High Data Rate

A single image can contain thousands or millions of pixels, creating much more data than typical environmental sensors.

Strict Timing

The MCU must capture data according to camera clock and synchronization timing.

Frame Buffers

Images generally require memory buffers for capture, processing and transmission.

Processing

Applications may require JPEG encoding, resizing, color conversion, computer vision or streaming.

Camera Power Requirements

Camera modules can have multiple voltage domains even when the module exposes only a small number of power pins.

Supply Purpose Important Consideration
Digital supply Digital logic Must match the sensor requirements.
Analog supply Sensor analog circuitry Noise can affect image quality.
I/O supply Digital interface voltage Must be compatible with MCU logic.
Ground Electrical reference Use appropriate grounding and power distribution.
Do not assume 3.3V is universally correct. Camera sensors can have separate internal supply domains. Follow the actual sensor/module electrical specification.

Camera Clock Architecture

MCU / Oscillator → XCLK → Camera Sensor

Camera Sensor → PCLK → MCU Camera Interface

The first clock provides a reference to the camera while the second is associated with the outgoing pixel stream.

SCCB / I2C-Style Camera Control

Many image sensors use a two-wire serial control interface derived from or compatible with an I2C-like architecture. OmniVision devices commonly refer to this control system as SCCB.

Signal Purpose
SIOC / SCL Serial control clock
SIOD / SDA Serial control data

The control interface is used to configure registers controlling resolution, frame format, exposure, gain, timing and other sensor parameters.

Common Camera Problems

Problem Possible Cause Check
Camera not detected Power or control-bus problem Verify supply, ground and sensor address/control bus.
No image Clock or data-capture configuration Check XCLK, PCLK and synchronization signals.
Corrupted image Incorrect timing or data-bit mapping Verify pixel clock and D0–D7 assignment.
Wrong colors Pixel format/configuration Verify RGB/YUV ordering and firmware configuration.
Image is shifted Synchronization/timing configuration Check VSYNC/HREF/HSYNC behavior.
Random frames Memory, timing or signal-integrity issue Check frame buffers, clocking and wiring.
Camera works intermittently Power integrity or signal integrity Check decoupling, supply stability and wiring.

Camera Engineering Rules

  • Identify the exact sensor. Do not assume two similarly named camera modules have identical pinouts.
  • Identify the exact module. Breakout boards can contain regulators, oscillators, level shifting and other circuitry.
  • Verify the control protocol. SCCB and I2C-like interfaces should not automatically be treated as identical without checking the documentation.
  • Verify XCLK requirements. Camera sensors are timing-sensitive devices.
  • Map the entire pixel bus. D0–D7 must correspond to the expected MCU inputs.
  • Verify synchronization polarity and timing. VSYNC, HREF and HSYNC behavior is sensor-specific.
  • Check memory requirements. Frame buffers can consume significantly more memory than ordinary embedded sensor data.
  • Protect the power system. Image sensors can be sensitive to supply noise.
  • Keep high-speed wiring short. Parallel camera buses are more sensitive to signal integrity than simple GPIO connections.

Embedded Camera Stack

Lens → Image Sensor → Sensor Configuration → Pixel Bus → Camera Interface → Frame Buffer → Image Processing → Application

Understanding this complete path is essential when debugging an embedded camera system. A failure at any layer can result in a camera that appears not to work.

Canonical Camera Reference

For production hardware designs, the authoritative sources should be the exact image-sensor datasheet, module schematic, module pinout and MCU technical documentation.

  • Use the exact sensor datasheet for electrical requirements.
  • Use the exact module schematic for connector/pin assignments.
  • Use the MCU reference manual for camera-interface capabilities.
  • Use the firmware/library documentation for driver behavior.
  • Treat generic camera pinouts as conceptual references only.
