RFID & NFC Readers

A hardware reference for RC522/MFRC522, PN532 and related 13.56 MHz RFID/NFC readers, including pinouts, SPI, I2C, UART, power, wiring, antennas and microcontroller integration.

RFID NFC RC522 MFRC522 PN532 SPI I2C UART

Reference Scope

RFID and NFC are related technologies, but a reader module, controller IC, antenna, tag/card and software library are separate components of the overall system.

Important distinction: The RC522 is primarily an MFRC522-based 13.56 MHz contactless reader/writer module. PN532-based modules provide a broader NFC feature set and support additional communication interfaces and operating modes.

RC522 / MFRC522

Low-cost 13.56 MHz reader/writer commonly used with MIFARE-class cards and tags.

PN532

Popular NFC controller supporting multiple host interfaces and a wider range of NFC/contactless functions.

13.56 MHz

RC522 and PN532 modules operate in the high-frequency contactless RFID/NFC range.

Host Interface

The reader communicates with the MCU through interfaces such as SPI, I2C or UART depending on the hardware.

RFID vs NFC

Term Meaning Typical Embedded Use
RFID Radio-frequency identification Identification and tag/card reading
NFC Near Field Communication Short-range contactless communication
HF RFID High-frequency RFID, commonly 13.56 MHz Cards, tags and access systems
Reader Device that communicates with a contactless tag Card/tag detection and communication
Tag Passive or active contactless device Identification/data storage

RC522 / MFRC522

The RC522 module is one of the most common low-cost RFID reader boards used in Arduino and ESP32 projects.

Many boards sold as "RC522" modules are breakout boards built around the NXP MFRC522 reader IC.

Frequency

13.56 MHz high-frequency contactless operation.

Host Interfaces

Common breakout implementations expose SPI. Some variants also provide I2C or serial configuration options.

Typical Cards

Commonly used with compatible MIFARE and ISO/IEC 14443 contactless cards and tags.

Supply

The MFRC522 IC is a low-voltage device. Verify the actual breakout board's power and logic requirements before wiring.

RC522 + ESP32

The ESP32 is particularly convenient for the RC522 because its GPIO and SPI peripherals are designed around 3.3V logic.

Understanding SPI

SPI allows multiple peripherals to share the clock and data signals while each device receives its own chip-select line.

SPI Signal Direction RC522 Role
SCK MCU → peripherals Clock
MOSI MCU → peripherals Commands/data
MISO Peripherals → MCU Responses/data
CS / SS MCU → peripheral Select RC522

Multiple SPI devices can share SCK, MOSI and MISO when their chip-select lines are managed correctly.

Multiple RC522 Readers on One MCU

Multiple SPI readers can share the same SPI bus. Each reader should normally have its own chip-select line.

Example Architecture

Signal Reader 1 Reader 2 Reader 3
SCK Shared Shared Shared
MOSI Shared Shared Shared
MISO Shared Shared Shared
SS / CS GPIO A GPIO B GPIO C
RST GPIO A2 GPIO B2 GPIO C2
RF warning: Multiple readers operating in close physical proximity can interfere with each other at the RF level even when their digital SPI connections are electrically correct.

PN532 NFC Reader

PN532 modules are another major category of 13.56 MHz contactless reader used in Arduino, ESP32 and embedded NFC projects.

Unlike the simple RC522 breakout, PN532 modules are commonly available with several host-interface options.

SPI

Uses a clocked serial interface and chip-select control.

I2C

Uses SDA and SCL and can simplify wiring when SPI pins are already occupied.

UART

Serial host communication is available on supported PN532 configurations.

NFC Features

PN532-based hardware is commonly selected when broader NFC functionality is required.

Cards, Tags & Contactless Objects

Reader compatibility depends on the actual RF protocol and tag technology. A tag being physically similar to another card does not guarantee that every reader can communicate with it.

Category Example Important Consideration
HF RFID 13.56 MHz tags Reader must support the relevant protocol
MIFARE MIFARE-family cards Different products have different capabilities
NFC tag NDEF-compatible tag Reader/controller must support the required NFC operation
UID Card identifier UID is not automatically equivalent to secure authentication
Security note: Treating a card UID as a secret credential is generally not sufficient for a security-sensitive system. Use the appropriate cryptographic authentication mechanism for the card technology and application.

Arduino RC522 Example

A basic RC522 application can use the Arduino SPI library together with an MFRC522-compatible library. 

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9

MFRC522 rfid(SS_PIN, RST_PIN);

void setup() {

  Serial.begin(115200);

  SPI.begin();

  rfid.PCD_Init();

  Serial.println("RFID reader ready");
}

void loop() {

  if (!rfid.PICC_IsNewCardPresent()) {
    return;
  }

  if (!rfid.PICC_ReadCardSerial()) {
    return;
  }

  Serial.print("UID:");

  for (byte i = 0; i < rfid.uid.size; i++) {

    Serial.print(" ");

    if (rfid.uid.uidByte[i] < 0x10) {
      Serial.print("0");
    }

    Serial.print(
      rfid.uid.uidByte[i],
      HEX
    );
  }

  Serial.println();

  rfid.PICC_HaltA();

  rfid.PCD_StopCrypto1();
}

ESP32 RC522 Example

The ESP32 can use the same MFRC522 software model while assigning the reader to the desired SPI GPIOs. 

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN   5
#define RST_PIN 27

#define SPI_SCK  18
#define SPI_MISO 19
#define SPI_MOSI 23

MFRC522 rfid(SS_PIN, RST_PIN);

void setup() {

  Serial.begin(115200);

  SPI.begin(
    SPI_SCK,
    SPI_MISO,
    SPI_MOSI,
    SS_PIN
  );

  rfid.PCD_Init();

  Serial.println("ESP32 RFID reader ready");
}

void loop() {

  if (!rfid.PICC_IsNewCardPresent()) {
    return;
  }

  if (!rfid.PICC_ReadCardSerial()) {
    return;
  }

  Serial.print("UID:");

  for (byte i = 0; i < rfid.uid.size; i++) {

    Serial.print(" ");

    if (rfid.uid.uidByte[i] < 0x10) {
      Serial.print("0");
    }

    Serial.print(
      rfid.uid.uidByte[i],
      HEX
    );
  }

  Serial.println();

  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}

Typical RFID Software Flow

  1. Initialize the SPI/I2C/UART host interface.
  2. Initialize the RFID/NFC controller.
  3. Check whether a card or tag is present.
  4. Anti-collision and protocol handling occurs.
  5. Read the required card/tag information.
  6. Authenticate when the card technology requires it.
  7. Process the application data.
  8. Stop or terminate the current card session.
  9. Return to the detection loop.

RF Antenna Considerations

The digital wiring between the reader and MCU is only one part of an RFID system. The RF antenna and surrounding physical environment strongly affect reader performance.

Antenna Geometry

The reader's antenna is designed for a particular RF operating environment. Do not arbitrarily modify the antenna circuit.

Metal

Nearby metal can significantly affect antenna behavior and contactless communication.

Distance

Contactless systems are designed for relatively short ranges. Actual range depends on the reader, tag, antenna, orientation and environment.

Orientation

Reader and tag antenna orientation can affect coupling and therefore communication reliability.

Common RFID Problems

Problem Possible Cause Check
Reader not detected Power or SPI wiring problem Check VCC, GND, SCK, MOSI, MISO and SS
Reader initializes but no tag RF/tag compatibility or antenna issue Verify supported tag type and orientation
Random SPI failures Voltage, wiring, timing or signal integrity Check logic levels and wiring length
Works on one board but not another Different voltage or SPI pin assignments Verify MCU-specific pin mapping
Card UID appears but data fails Protocol or authentication issue Verify card technology and access procedure
Short read distance Antenna/environment limitations Remove nearby metal and test orientation

Power & Logic-Level Rules

  • Identify the actual reader IC. "RC522 module" describes a common breakout category, not every possible board design.
  • Verify VCC. The MFRC522 IC is a low-voltage device. Follow the module/controller electrical specifications.
  • Do not assume 5V tolerance. MCU GPIO voltage compatibility must be verified before connecting a 5V Arduino directly to a 3.3V RFID controller.
  • Use a common ground. The MCU and reader need a compatible signal reference.
  • Keep SPI wiring reasonable. Long jumper wires can introduce signal-integrity problems.
  • Do not treat a UID as a secret. Security-sensitive applications require appropriate authentication and cryptographic design.
  • Verify tag compatibility. Not every 13.56 MHz card uses the same protocol or feature set.
  • Protect the RF section. Mechanical placement, metal, cables and enclosure materials can affect antenna performance.

RFID Engineering Checklist

  • Identify the reader IC and breakout board.
  • Identify the supported RF frequency and protocol.
  • Verify VCC and digital logic levels.
  • Identify the host interface: SPI, I2C or UART.
  • Map every signal to the selected MCU.
  • Verify that the MCU has the required SPI/I2C/UART resources.
  • Verify tag/card compatibility.
  • Test the reader away from large metal surfaces.
  • Test card orientation and distance.
  • Separate identification from authentication in security-sensitive applications.
